NEW AND DELETE.
    -> Basicamente são os *alloc() e o free() mas em c++. O new é o equivalente ao alloc e o delete ao free.

    -> A grande diferenca é que tanto o new quanto o delete conseguem chamar o construtor e o destrutor de
    classes que nós criamos. O alloc e o free não conseguem "achar" as classes que criamos, consequentemente,
    não chamam os construtores e destrutores.

    -> Sintaxe:
        ClassName   *teste = new ClassName("allan");  -> "Estamos alocando dinamicamente uma instancia de ClassName."

        delete teste;  -> "Estamos deletando, limpando, a memoria alocada pelo ptr teste do tipo
                            ClassName."

        ClassName   *teste = new ClassName[42];  -> "Estamos alocando um array do tipo ClassName de 
                                                        tamanho 42."
        delete [] teste;  -> "Estamos limpando, deletando, a memoria alocada pelo ptr teste do tipo
                                ClassName."

FIXED POINT NUMBERS.
    -> Pelo que eu entendi, basicamente é uma forma de "corrigir" o problema que temos com
    flaoting point varibles. Isto é, para termos uma precisão das casas decimais (fracionais)
    o float não é suficiente, demandando assim, a implementacao dos fixed points values.

    -> Esse link tem as formulas abaixo com outras explicações importantes:
    https://people.ece.cornell.edu/land/courses/ece4760/PIC32/index_fixed_point.html

    -> Para fazermos uma multiplicação de dois fixed point, temos essa formula:
        ((fix))((((singned long long a))*((signed long long b)) >> 15))

        "Basicamente castamos o valor para signed long long para termos 64 bits
        de tamanho, depois disso fazer uma operação de bitwise 15 para a direita.
        Isto é, jogamos o valor todo 15 casas para a direita para caber tudo depois
        nos 32 bits de tamanho do fixed point."

    -> Para transformarmos signed int to fix, temos essa formula:
        ((fix))((a << 15))
        
        "O valor 15 pode variar dependendo da posição que desejamos incluir o decimal.
        Isto é, o '.'"

    -> Para transformarmos fix to a signed int, temos essa formula:
        ((int))((a >> 15))

        "O valor 15 pode variar dependendo da posição que desejamos incluir o decimal.
        Issto é, o '.'"

    -> Para transformarmos floating point value to a fixed point, temos a formula:
        ((fix))(a * 32768.0)

    -> Para transformarmos fixed point to a floating point, temos a formula:
        ((float)(a) / 32768.0)

    -> Para fazermos uma divisao temos a seguinte formula:
        ((fix))((((signed long long)(a) << 15 / (b))))

    -> Para fazermos a raiz quadrada temos a formula:
        (float2fix(sqrt(fix2float(a))))

INHERITANCE IN C++.
    -> Basicamente, a herança é uma forma de compartilhar o código já escrito. Isto é, uma forma 
    de evitar escrever código mais de uma vez.

    -> Então, ao declararmos uma classe ANIMAL que possui uma member function EAT(), e queremos
    criar também, uma classe apenas de DOGS:
    EX:

        class animal
        {
            protected:
                std::string type;
            private:
                std::string name;
            public:
                void eat(void);
                ...
        }

        class dog
        {
            private:
                std::string name;
                std::string owner;
            public:
                void play(void);
                void eat(void);
                ...
        }

    -> No caso acima, a classe dog possui a mesma funcionalidade da classe animal. Entao, estamos
    escrevendo o "mesmo código" mais de uma vez.

    -> Podemos fazer dessa maneira:

        class animal
        {
            private:
                std::string name;
            public:
                void eat(void);
                ...
        }

        class dog : public animal
        {
            private:
                std::owner;
            public:
                void play(void);
                ...
        }

    -> Se instanciarmos um objeto de dog, ele terá acesso a todos os public atributos da classe animal.
    Pois a classe dog herda da classe animal. Entao:

        int main(void)
        {
            dog auau("totó", "allan"); -> construtor(nome do cao, nome do dono);

            auau.play(); -> auau tem acesso ao método play() pois foi declarado na classe dog.
            auau.eat(); -> auau também tem acesso ao metodo eat() pois a classe dog herda da classe animal.
            std::cout << auau.name std::endl; -> auau NAO consegue acessar o atributo name da classe animal 
                                                    pois esta setado como private. Entao so temos acesso
                                                    atraves de um metodo public: ou se ele fosse protected:
            std::cout << auau.type std::endl; -> auau TEM acesso ao atributo type pois ele esta setado como protected.
        }

    -> Então, sempre que criarmos uma classe B que herda de outra classe A, TUDO que, dentro da classe A,
    tiver setado como PUBLIC: a classe B tem acesso.

    -> TUDO que estiver setado como PRIVATE: dentro da classe A, a classe B NÃO tem acesso. Só consegue acessar
    se tiver algum método PUBLIC: que acessa o atributo PRIVATE:

    -> TUDO que estiver setado como PROTECTED: dentro da classe A, a classe B TEM acesso.

CLASSE BASE E VIRTUAL FUNCTIONS.
    -> Bom link de um vídeo: https://www.youtube.com/watch?v=rECcII1Mdfc

    -> Basicamente, o prefixo virtual, indica ao compilador que as virtual functions serao
    decididas no momento de execucao, nao de compilacao. Isto é, se temos:

        class Base
        {
            private:

            public:
            ...
                void print(void) const {std::cout << "BASE" << std::endl;}
        }

        class Derived : public Base
        {
            private:

            public:
            ...
                void print(void) const {std::cout << "DERIVED" << std::endl;}
        }

        void test(const Base &object)
        {
            object.print();
        }
        
        int main(void)
        {
            Base t1;
            Derived t2;

            test(t2);
        }

        -> No caso acima, o compilador decide que, qualquer objeto da classe Base, ao chamar
        a function print, vai usar a function definida no escopo da classe Base.
            Só que isso acaba gerando um problema para o nosso código. Pois, no exemplo acima,
        a classe Derived é, tambem, uma classe Base, pois ela é filha da Base. Entao, ao
        chamarmos a function test() que recebe um objeto do tipo Base, ela pode receber QUALQUER
        classe que seja Base.
            Dessa maneira, a function print() que será chamada vai ser a que a classe Base declarou
        no seu escopo.

        -> Para resolvermos esse problema, basta colocar o prefixo VIRTUAL na frente da function
        print() dentro da definicao da classe Base, isto é, da clase PAI.

IMPORTANTE!!!

    VIRTUAL = DYNAMIC BINDING = OVERRINDING
            |
            |
            ---> Dessa maneira, fazemos que o compilador defina qual vai ser a declaracao da function
            que vai ser chamada na hora de executa-la. (DINAMICAMENTE)

    STATIC BINDING = REDEFINIG
            |
            |
            ---> Dessa outra maneira, o compilador decide qual declaracao vai ser chamada, na hora
            que o codigo foi compilado.

IMPORTANTE 2!!!!
    -> PARA USARMOS O POLIMORFISMO, PRECISAMOS USAR PONTEIROS E REFERENCIAS NA DECLARAÇÃO DOS NOSSOS OBJETOS.
    CASO CONTRARIO, MESMO QUE A DECLARACAO DE UMA FUNCTION DENTRO DE UMA BASE CLASS ESTEJA COMO VIRTUAL,
    SERA USADO O STATIC BINDING.

IMPORTANTE 3!!!
    -> Quando queremos fazer essa atribuicao:
    ...
        Derived t1();
        Base *test = &t1;
            |
            |
            ---> Isso pode, pois uma instancia de derived é, necessariamente, uma instancia de Base.
        
        Base t2();
        Derived *test2 = &t2;
            |
            |
            ---> O oposto nao ocorre. Pois uma instancia de Base nao é uma instancia de Derived.

VIRTUAL FUNCTION TABLE.
    -> Quando um destrutor é virtual, o compilador cria uma tabela de funções virtuais (vtable), 
    que garante que a função correta seja chamada em tempo de execução. Assim, se meta for um 
    ponteiro para uma classe derivada, o destrutor da classe derivada será chamado 
    antes do destrutor da base.

CLASS ABSTRATA.
    ->  O primeiro conceito importante das classes abstratas é que elas não podem ser instanciadas...
    Isto é, não podemos ter um objeto de uma classe abstrata.
        Mas podemos ter uma outra classe que deriva dessa classe abstrata e podemos instanciar um
    objeto dessa nova classe.

    ->  Uma 'PURE VIRTUAL FUNCTION' é uma member function que precisa ser redefinida pela
    classe derivada. Isto é, pela classe que herda da classe abstrata.

    ->  Quando uma classe tem uma 'PURE VIRTUAL FUNCTION' como member function ela se torna uma Classe abstrata.

    ->  ABSTRACT BASE CLASS NAO PODEM SER INSTANCIADAS NUNCA!!!!!
            |
            |
            ---> Entao, tudo que derivar desta classe abstrata, PRECISARA sobrescrever a PURE VIRTUAL FUNCTION.
            Isto é, precisara dar o override das funções que estao como virtual.

    EXEMPLO:
        #include <iostream>

        class Foo
        {
            public:
                virtual void print(void) const = 0;
        };

        class Bar: public Foo
        {
            public:
                virtual void print(void) const {std::cout << "Hello from Bar!" << std::endl;}
        };

        int main(void)
        {
            Foo test;   -> NAO FUNCIONA. Pois a class Foo é uma classe Abstrata. "O próprio compilador reclama."
            Bar teste;  -> Funciona pois a classe Bar deriva da classe base (abstrata) e faz o override da function print().

            return (0);
        }

    EXEMPLO 2:
        #include <iostream>

        class Foo
        {
            public:
                virtual void print(void) const = 0;
        };

        class Bar: public Foo
        {
            public:
                virtual void print(void) const {std::cout << "Hello from Bar!" << std::endl;}
        };

        class Spam: public Foo
        {
            public:
                virtual void print(void) const {std::cout << "Hello from Spam!" << std::endl;}
        };

        int main(void)
        {
            //Foo test;
            Bar teste;  -> Funciona pois deriva da classe abstrata Foo e faz o override da virtual print() function.
            Spam test;  -> Funciona pois deriva da classe abstrata Foo e faz o override da virtual print() function.

            test.print();   -> Usando a function overriden
            teste.print();  -> Usando a function overriden

            return (0);
        }

    EXEMPLO 3:
        #include <iostream>

        class Foo
        {
            public:
                virtual void print(void) const = 0;
        };

        class Bar: public Foo
        {
            public:

        };

        };

        class Eggs: public Foo

            public:

IMPORTANTE:
    -> Quando criamos uma classe que deriva de uma classe abstrata, precisamos SEMPRE dar o override das virtual functions.

    -> Mas essa nova classe pode criar seus próprios métodos e atributos de maneira independente!!!

EXCEPTIONS.
    -> Usamos as exceptions para lidar com diversos tipos de erros durante a execução do nosso código.
    Isto é, quando usamos o "try catch", estamos fazendo uma espécie de tratamento de erros. Então,
    sempre que um "throw" jogar uma exception, vamos pegar com o "catch" e lidar com esse erro da
    melhor maneira. 

    -> Usando as exceptions, fazemos o nosso código não crashar/quebrar com erros inesperados.

    -> Quando damos um "throw" de uma execption, o código automaticamente para de rodar a function. 
    Então, não precisamos retornar...

    -> A estrutura que usamos para "Pegar" uma exception é a seguinte:
        try
        {
            "O código que você quer tentar rodar."
        }
        catch ("O tipo de exception que você quer pegar, isto é, o tipo de erro no 'throw'.")
        {
            "O que você quer que aconteca caso você pegue o erro..."
        }
        catch (...) -> Nesse caso, estamos aceitando qualquer tipo de erro jogado pelo 'throw'!
        {
            "O que você quer fazer nesse caso de erro..."
        }

        IMPORTANTE: "O último caso, chamado de default handler, PRECISA estar como última opção.
                    Caso contrário, o compilador deve acusar um error."

                    "É como se fosse o default do switch case..."

COMO FUNCIONA AS EXCEPTIONS:
    Link com todas as classes derivadas:
        https://en.cppreference.com/w/cpp/error/exception

                        exception       -> Class base
                            |
                            |
            ---------------------------------
            |               |               |
        logic_error     Bad_alloc       run_time_error      -> Classes derivadas da classe base exception
            |
        out_of_range        -> Classe derivada de logic_error, que deriva da classe base exception

    -> "Então, se quisermos ser bem genericos no nosso catch, podemos fazer dessa forma:"

        try
        {
            ...
        }
        catch (exception& e)
        {
            std::cerr << "Exception: " << e.what() << std::endl;
        }
            "Como todas as exceptions derivam da classe base exception, esse catch vai dar conta
            de todos as exceptions possíveis."

    -> É considerado Boa prática lidar com as exceptions do jeito mais específico possível. 
    Isto é, evitar dar catch() em erros genéricos. Por exemplo:
        try
        {
            ...
        }
        catch (...)                                                -> Jeito não tão legal.
        {
            "generic exception"
        }

        OU

        try
        {
            ...
        }
        catch (std::exception &e)                                  -> Jeito não tão legal.
        {
            std::cout << "Exception: " << e.what() << std::endl;
        }

CASTING EM C++.
    -> Type casting é a forma que podemos mudar o tipo de uma variavel. Isto é, se temos uma variavel do tipo INT
    e queremos transformar o valor para DOUBLE, podemos fazer o type casting para o novo tipo de dado.

        int value = 42;
        double new = value;

            OU                                                              -> Ambos exemplos são em C.
        
        double value = 2.3;
        int value2 = 2;
        double result = (int)(value + value2); -> result = 4.0;

    -> Temos dois tipos de type casting. Casting IMPLÍCITO e EXPLÍCITO. Os exemplos acima são representações
    deles respectivamente.

    -> Em alguns casos, tanto com o IMPLÍCITO quanto com o EXPLÍCITO, principalmente com tipos de dados numéricos, 
    dependendo do casting que desejamos fazer, podemos ter a perda de precisão. Nesses casos, o compilador 
    pode nos avisar com um warning.

    -> Em C++ podemos fazer da mesma maneira. Mas, temos uma maneira mais correta de se fazer o casting.

        double value = 5.25;
        double result = static_cast<int>(value) + 5.3;

    -> Bom link com os casts em c++: https://cplusplus.com/doc/oldtutorial/typecasting/

OBS: Esses tipos de casting em c++, não fazem nada de diferente em comparação aos castings em C.
    Isto é, podemos atingir os mesmos resultados usando o casting de C.

    -> Basicamente em c++ temos 4 tipos de casting:
        - dynamic_cast<new_type> (expression)
        - static_cast<new_type> (expression)
        - reinterpret_cast<new_type> (expression)
        - const_cast<new_type> (expression)

        -> Dynamic_cast<>():
            - Só pode ser usado com ponteiros e referências de objetos.
            - Seu objetivo é garantir que o resultado do CASTING seja um objeto completo da classe
            desejada. Isto é, da classe passada entre '<>'
            - Entretanto, o dynamic cast sempre vai ser bem sucedido quando castarmos
            uma classe para uma das suas classes base.

            exemplo:
                class CBase { };
                class CDerived: public CBase { };

                CBase b; CBase* pb;
                CDerived d; CDerived* pd;

                pb = dynamic_cast<CBase*>(&d);     // ok: derived-to-base
                pd = dynamic_cast<CDerived*>(&b);  // wrong: base-to-derived  -> Isso sempre vai acontecer
                                                                                a menos que a classe base 
                                                                                seja polimórfica!

        -> Static_cast<>():
            - Pode performar conversões entre ponteiros para classes relacionadas, não apenas entre
            classes derivadas para classe base, mas também, da classe base para classe derivada.
            - O static_cast garante que as classes são compatíveis se o objeto for castado. Mas não
            checa durante o tempo de execução se o objeto sendo convertido é, de fato, um 'full object'
            do tipo destino.

            - O static_cast pode ser usado para castar qualquer tipo de non-pointer convertion que
            possa ser castado de forma implícita.
            - Ou qulquer casting entre classes com construtores explícitos ou operators functions.

            exemplo:
                class CBase {};
                class CDerived: public CBase {};
                CBase * a = new CBase;
                CDerived * b = static_cast<CDerived*>(a);

            - Basicamente, nos permite fazer qualquer tipo de casting desde que as classes/tipos de dados
            desejados, possuam alguma relação com a expressão.
