    -> cin: Input

CLASS AND INSTANCES.
    -> Uma nova classe deve ser declarada em um arquivo .hpp. A implementacao dos deus métodos devem ser
    feitas no arquivo .cpp. Isto é, se temos uma classe chamada "Carros.hpp", todos os seus atributos e
    protótipos dos métodos devem estar declarados neste arquivo. Em um outro arquivo chamado Carros.cpp
    vamos implementar seus métodos, sejam os construtores/destrutores ou outros métodos.
        -> Então:
            NomeDaClasse.hpp = Declaracao dos atributos e protótipos dos métodos.
            NomeDaClasse.cpp = implementacao dos métodos.

INITIALIZATION LIST.
    Good link: https://www.geeksforgeeks.org/when-do-we-use-initializer-list-in-c/

    -> Basicamente, usar a "initializer list" ou lista de inicialização, é a forma mais correta de
    implementar os construtores das classes. No link acima tem várias explicações dos motivos.
    Mas, para resumir, evita o problema de conversões de estreitamento e comportamento inesperado. 
    Ela fornece verificação de tipo mais rigorosa durante a inicialização e previne conversões 
    de estreitamento em potencial. 
        Em outras palavras, é uma boa pratica que garante a não ocorrência de erros inesperados.

    -> Declaração da "parameter initialization":
        ClassName::ClassName(string nome, int idade)
        {
            this->nome = nome;
            this->idade = idade;
        }
    
    -> Declaração da "initialization list"
        ClassName::ClassName(string nome, int idade): nome(nome), idade(idade) {}

CONST.
    Good link: https://www.geeksforgeeks.org/const-keyword-in-cpp/

    -> O uso de constantes na programação é algo muito importante no mundo. Ainda não é algo que nós,
    da 42, usamos da melhor maneira, pois é meio limitado para nós. Mas, faz toda diferença no longo
    prazo. Acaba sendo um divisor de águas importante para os programadores.

    -> O uso do "CONST" é feito tanto em atributos quanto em métodos:
        -> Const nos atributos, assim como em variavies no geral, é uma forma de garantir que aquele
        atributo NUNCA vai mudar durante a execução do programa.

        -> Const nos métodos, é uma forma de mostrar para o compilador que aquele médoto com "const"
        explícito antes do ';' NÃO vai alterar a instância chamadora. Isto é, aquele método não vai 
        alterar o estado do objeto que chamou o método.
            |
            |
            ---> void metodoTest(void) const;
                    |
                    |
                    ---> void Classe::metodoTest(void) const {
                            "Não vai haver nenhuma alteração no estado daquela instância"
                            this->name = "Allan";
                                |
                                |
                                ---> "Isso não é aceito pelo compilador"
                    }

PUBLIC AND PRIVATE.
    -> Basicamente, é a forma de "proteger" ou não os atributos e métodos da classe. Isto é, se algum 
    atributo está setado como "private:", ele poderá ser acessado somente dentro da própria classe. 
        EX:
            "Se temos um atributo ou método private, uma instância dessa classe só pode acessa-lo 
            através de algum método public."
     -> Dessa forma garantimos que o usuário só acessaria o que realmente importa.

     -> Uma convenção é declarar o nome dos atributos ou médotos que são "private" com o '_' no 
     início.
        EX:
            class NomeDaClasse
            {
                private:
                    const int _cpf;
                    void    _setCpf(void) const;
                public:
                    ...
            }

    adicionar member functions para alterar o seu estado.

NON MEMBER ATTRIBUTES AND NON MEMBER FUNCTIONS.
    -> São médotos e atributos que não precisam de uma instância para serem acessados. Isto é, não
    precisam necessáriamente estar no escopo da classe em si, fazendo que não sejam "Mebers" da classe.

    -> Para declarar um atributo ou método como "NON MEMBER" colocamos o "STATIC" na frente da declaração.
    Mesmo que eles sejam static, a declaração do método static ainda é feita no arquivo .cpp da classe.
        EX:
            class ClassName
            {
                private:
                    static float _pi; -> para inicializar é ClassName::_pi = 3.1415 no .cpp da classe
                    ...
                public:
                    static float getPi(void); -> implementacao feita no .cpp da classe
                    ...
            }

            "Dessa forma, o atributo "pi" e o método "getPi" podem ser acessados sem precisar de uma
            instância da classe ClassName."
                |
                |
                ---> Sintaxe: "ClassName::getPi()"
            
            "No caso do NON MEMBER ATTRIBUTE, por estar como private, precisa de um getter para
            ser acessado."

NEW AND DELETE.
    -> Basicamente são os *alloc() e o free() mas em c++. O new é o equivalente ao alloc e o delete ao free.

    -> A grande diferenca é que tanto o new quanto o delete conseguem chamar o construtor e o destrutor de
    classes que nós criamos. O alloc e o free não conseguem "achar" as classes que criamos, consequentemente,
    não chamam os construtores e destrutores.

    -> Sintaxe:
        ClassName   *teste = new ClassName("allan");  -> "Estamos alocando dinamicamente uma instancia de ClassName."

        delete teste;  -> "Estamos deletando, limpando, a memoria alocada pelo ptr teste do tipo
                            ClassName."

        ClassName   *teste = new ClassName[42];  -> "Estamos alocando um array do tipo ClassName de 
                                                        tamanho 42."
        delete [] teste;  -> "Estamos limpando, deletando, a memoria alocada pelo ptr teste do tipo
                                ClassName."

REFERENCE AND POINTERS IN CPP.
    -> links:
        https://www.youtube.com/watch?v=sxHng1iufQE
        |
        ---> "In short: Pointers and references can be used to refer to data in memory, 
        without copying the data to a new variable. That is efficient. 
        While pointers can arbitrarily be changed to point to any memory addresses and need 
        a dereferentiation in order to read the value, references do refer to a fixed location 
        in memory and behave like normal variables (do not need dereferentiation),  
        when one wants to read their value. 
        However, since no data is copied from one var to another in either case, 
        changes made to these memory locations will be present instantly for pointers and references."

    -> Basicamente é um ponteiro const e esta sempre "dereferentiate" desrreferenciado e nunca é void.
    Isto é, ele é um clone de uma variável. Possuí o mesmo endereço e valor da variável "clonada" e 
    consegue alterar o valor da mesma através do clone.

    -> Não pode mudar de referencia. Isto é, uma vez referenciado a uma variavel, vai SEMPRE estar
    referenciado àquela variavel.

ADHOC POLYMORPHISM.
    -> Também conhecido como "function overloading ou overload de função". É basicamente uma maneira de
    declararmos duas ou mais functions com o mesmo nome porém com parâmetros diferentes. Isto é, podemos
    ter dois métodos com o mesmo nome.
    Por ex:
        ClassName(void) e ClassName(std::string name);

        void ClassName::setName(void) e void ClassName::setName(std::string name);

ORTHODOX CANONICAL FORM.
    -> Basicamente, parece ser uma forma padrão para escrever classes. Sendo considerado apenas uma
    boa prática. 

        A default constructor: "used internally to initialize objects and data members when 
                                no other value is available."

        A copy constructor: "used in the implementation of call-by-value parameters."
            -> É usado para copiar uma instância de uma classe. Isto é, o construtor receberá uma instância
            já existente e a nova instância recebera essa já existente, criando uma cópia.

        An assignment operator: "used to assign one value to another."
            -> Mesma ideia do "copy constructor", com a diferença de que ambas instancias já são existentes.
        
        A destructor: "Invoked when an object is deleted."
